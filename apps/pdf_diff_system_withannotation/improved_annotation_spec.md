# 改善版アノテーション仕様書

## 1. 概要
PDF差分検出システムの評価精度を向上させるため、アノテーションデータの仕様を改善します。

## 2. 現状の問題点

### 2.1 変更タイプの粒度
- すべての変更が「変更」として記録され、削除・追加・修正の区別がない
- アルゴリズムが3種類の差分を報告するため、適合率が低下（33.3%）

### 2.2 文脈情報の不足
- 単独のテキスト片のみが記録され、周辺コンテキストがない
- フレーズ境界が不明確で、部分一致の判定基準が曖昧

### 2.3 評価基準の曖昧さ
- 「iOS 11/12/13/14/15/16」と「11/12/13/14/15/16」のような境界問題
- どこまでが正解とすべきか不明確

## 3. 改善案

### 3.1 CSVフォーマット改善案

```csv
要素ID,前年ページ,後年ページ,変更タイプ,前年テキスト,後年テキスト,前年前文脈,前年後文脈,後年前文脈,後年後文脈,マッチング方式,重要度,備考
00001,1,1,MODIFICATION,令和5年度,令和6年度,"","保存版","","保存版",exact,HIGH,年度変更
00002,1,1,ADDITION,,"MS1を閲覧できる方、ご自宅の...","","","","につきましては、",partial,MEDIUM,説明文追加
00003,1,1,DELETION,夫婦補償,,"","家族補償","","",exact,MEDIUM,補償種別削除
```

### 3.2 変更タイプの定義

| 変更タイプ | 説明 | 例 |
|-----------|------|-----|
| MODIFICATION | テキストの修正 | 「令和5年」→「令和6年」 |
| ADDITION | 新規追加 | なし→「新しい説明文」 |
| DELETION | 削除 | 「古い説明文」→なし |
| REORDER | 順序変更のみ | 位置が変わっただけ |
| MERGE | 複数要素の統合 | 「A」「B」→「AB」 |
| SPLIT | 要素の分割 | 「AB」→「A」「B」 |

### 3.3 マッチング方式

| 方式 | 説明 | 使用場面 |
|------|------|----------|
| exact | 完全一致必須 | 固定フォーマットのテキスト |
| partial | 部分一致許可 | 長文や可変部分を含むテキスト |
| semantic | 意味的一致 | 「p34」と「34ページ」など |
| regex | 正規表現マッチ | パターンベースの変更 |

### 3.4 文脈情報の記録

- **前文脈/後文脈**: 対象テキストの前後20-50文字を記録
- **フレーズ境界**: 句読点、改行、特定の区切り文字で明示
- **構造情報**: 見出し、本文、箇条書きなどの文書構造上の位置

### 3.5 重要度レベル

| レベル | 説明 | 例 |
|--------|------|-----|
| HIGH | 必須検出項目 | 年度、金額、URL |
| MEDIUM | 重要項目 | 説明文、注意事項 |
| LOW | 補助的項目 | 装飾的な変更 |

## 4. 評価方法の改善

### 4.1 スコアリング
```python
# 変更タイプ別の重み付け
weights = {
    'MODIFICATION': 1.0,
    'ADDITION': 1.0,
    'DELETION': 1.0,
    'REORDER': 0.5,  # 順序変更は重要度低
    'MERGE': 0.8,
    'SPLIT': 0.8
}

# 重要度による重み付け
importance_weights = {
    'HIGH': 1.0,
    'MEDIUM': 0.7,
    'LOW': 0.3
}
```

### 4.2 評価指標
- **タイプ別適合率/再現率**: 変更タイプごとに評価
- **重み付きF1スコア**: 重要度を考慮した総合評価
- **境界精度**: フレーズ境界の一致度

## 6. 移行計画

1. **既存アノテーションの変換**
   - 現在の「変更」を適切なタイプに分類
   - 文脈情報を自動/手動で追加

2. **段階的導入**
   - まず重要な変更（HIGH）から新仕様を適用
   - 評価結果を見ながら調整

3. **ツール開発**
   - アノテーション作成支援ツール
   - 既存データの変換スクリプト

## 7. 期待される効果

1. **評価精度の向上**
   - 適合率の改善（33.3% → 80%以上を目標）
   - より詳細な性能分析が可能

2. **アルゴリズム改善の指針**
   - 変更タイプ別の弱点が明確に
   - 優先的に改善すべき箇所の特定

3. **開発効率の向上**
   - 明確な評価基準による迅速な判断
   - 誤検出パターンの体系的な分析
