# 表マッチングシステム実装・修正ログ

## 概要
LLM差分検出システムv3-3における表構造を考慮した差分検出機能の実装と改善の記録。

## 1. 初期実装（表検出機能の追加）

### 1.1 基本構造
- **目的**: PDFドキュメント内の表を検出し、表単位で差分を検出する
- **技術**: Azure Document Intelligence の `prebuilt-layout` モデルを使用
- **アプローチ**: 表と非表テキストを分離して処理

### 1.2 主要コンポーネント
1. **TableMatcher** (`core/table_matcher.py`)
   - ヘッダー行の総当たりマッチング
   - セル類似度0.8以上でマッチング判定
   - 構造類似度 = ヘッダー類似度 × 0.7 + サイズ類似度 × 0.3

2. **TableAwareDiffDetector** (`core/table_aware_diff_detector.py`)
   - 表の抽出と分離
   - 表外テキストの差分検出
   - 表内差分の検出

3. **TableDiffResult** (`models/table_models.py`)
   - 表の差分結果を格納するデータクラス
   - JSON シリアライズ対応（`to_dict()` メソッド）

## 2. 主要な修正履歴

### 2.1 バウンディングボックス座標変換の修正
**問題**: Azure Document Intelligenceから取得した座標（インチ単位）をPDFハイライト用（ポイント単位）に変換していなかった

**修正内容**:
```python
# handlers/output_handler.py
# インチからポイントに変換（1インチ = 72ポイント）
bbox_points = [coord * 72 for coord in cell['bbox']]
```

**影響範囲**:
- 削除された表全体のハイライト
- 追加された表全体のハイライト
- 個別セルのハイライト

### 2.2 行マッチングアルゴリズムの実装
**問題**: 行が挿入・削除された場合、それ以降のすべての行が差分として検出される

**修正内容**:
1. **行見出し（1列目）による総当たりマッチング**
   ```python
   # _match_rows_by_headers メソッドを追加
   # 1列目のテキストで類似度0.8以上の行をマッチング
   ```

2. **row2 フィールドの追加**
   ```python
   cell_changes.append({
       'row': row1,    # 表1の行番号
       'row2': row2,   # 表2の行番号（新規追加）
       'column': col,
       # ...
   })
   ```

3. **ハイライト処理での row2 使用**
   ```python
   target_row = cell_change.get('row2', cell_change.get('row'))
   ```

### 2.3 ハイライト粒度の変更
**変更履歴**:
1. セル単位のハイライト（初期実装）
2. 行単位のハイライト（行全体を囲む）
3. セル単位のハイライトに戻す（最終）
4. すべてのハイライトを赤色に統一

### 2.4 MeCabによる詳細解析の追加
**実装内容**:
- **CellTextAnalyzer** (`core/cell_text_analyzer.py`)
  - セル内テキストを文単位に分割
  - 形態素解析による詳細な差分検出
  - 差分タイプの判定（minor_change, partial_change, major_change）

**特徴**:
- 文単位での差分検出
- 変更された形態素の特定
- 差分の重要度判定

### 2.5 表マッチング精度の改善
**問題**: 異なる表が誤ってマッチングされる（例: sample2での誤マッチ）

**修正内容**:
1. **構造類似度の閾値引き上げ**: 0.6 → 0.7
2. **最小ヘッダーマッチ数の設定**: 2個以上必要
3. **1列目（行見出し）の類似度を考慮**:
   ```python
   # 新しい重み配分
   structure_similarity = header_similarity * 0.5 + row_header_similarity * 0.3 + size_similarity * 0.2
   ```

## 3. デバッグ機能

### 3.1 TableDebugHandler
- 表検出結果をJSON形式で保存
- 各表をCSV形式で保存（`debug/tables/` ディレクトリ）
- マッチング結果の詳細情報を出力

### 3.2 デバッグファイル
- `table_detection.json`: 検出された表の情報
- `table_matching.json`: 表マッチングの詳細
- `table_diffs.json`: 表の差分情報
- `table1_*.csv`, `table2_*.csv`: 各表のCSVデータ

## 4. 設定とコマンドライン

### 4.1 コマンドライン引数
```bash
--use-table-detection    # 表検出機能を有効化
--no-table-detection     # 表検出機能を無効化（デフォルト）
```

### 4.2 実行例
```bash
poetry run python test_llm_diff_v3.py --dataset sample1 --use-table-detection --no-high-resolution --max-pages 5
```

## 5. 既知の問題と今後の改善点

### 5.1 解決済みの問題
- ✅ バウンディングボックスのハイライトが表示されない
- ✅ 行の挿入・削除で後続行がすべて差分になる
- ✅ 異なる表が誤ってマッチングされる

### 5.2 今後の改善候補
1. **セル内の行単位ハイライト**: 現在はセル全体をハイライトするが、セル内の変更行のみをハイライトする機能
2. **表の列マッチング**: 列の挿入・削除にも対応
3. **複雑な表構造への対応**: 結合セルやネストされた表
4. **パフォーマンス最適化**: 大量の表を含む文書での処理速度改善

- sample2: 表マッチング精度改善により、誤マッチを防止
