# フレーズ分割アルゴリズム詳細分析

## 1. 概要

PhraseBasedDiffDetectorの中核となるフレーズ分割処理の詳細分析と問題点を記録します。

## 2. 現在の分割プロセス

### 2.1 処理の流れ

```
入力テキスト
↓
基本分割（区切り文字）
↓
形態素解析（MeCab）
↓
フレーズ結合
↓
フレーズタイプ分類
↓
最終フレーズリスト
```

### 2.2 実際の分割例

#### 例1: 年度変更
```
入力: "令和5年度 保存版"
↓
基本分割: ["令和5年度", "保存版"]
↓
形態素解析:
- 令和 (名詞-固有名詞)
- 5 (名詞-数)
- 年度 (名詞-接尾)
- 保存 (名詞-サ変接続)
- 版 (名詞-接尾)
↓
フレーズ結合: ["令和5年度", "保存版"]
↓
タイプ分類:
- "令和5年度" → タイプ: 年度
- "保存版" → タイプ: 一般
```

#### 例2: iOS バージョン（問題ケース）
```
入力: "iOS 11/12/13/14/15/16"
↓
基本分割: ["iOS", "11/12/13/14/15/16"]
↓
形態素解析:
- iOS (名詞-一般)
- 11 (名詞-数)
- / (記号-一般)
- 12 (名詞-数)
- ...
↓
フレーズ結合: ["iOS", "11/12/13/14/15/16"]
↓
タイプ分類:
- "iOS" → タイプ: iOS
- "11/12/13/14/15/16" → タイプ: バージョン
```

## 3. 分割の問題点と具体例

### 3.1 境界判定の曖昧さ

#### 問題例1: スペースによる分割
```
アノテーション: "iOS 11/12/13/14/15/16"
システム分割: ["iOS", "11/12/13/14/15/16"]
```
→ スペースで分割されるため、アノテーションと不一致

#### 問題例2: 複合語の扱い
```
入力: "団体総合生活補償保険(MS&AD型)"
可能な分割:
1. ["団体総合生活補償保険(MS&AD型)"]  # 全体を1フレーズ
2. ["団体総合生活補償保険", "(MS&AD型)"]  # 括弧で分割
3. ["団体", "総合", "生活", "補償", "保険", "(MS&AD型)"]  # 形態素単位
```

### 3.2 文脈依存の問題

#### 例: ページ参照
```
文書1: "詳細はp34をご覧ください"
文書2: "詳細はp35をご覧ください"

現在の分割:
- ["詳細は", "p34", "をご覧ください"]
- ["詳細は", "p35", "をご覧ください"]

理想的な分割:
- ["詳細はp34をご覧ください"]  # 文全体で意味を持つ
```

### 3.3 日本語特有の問題

#### 助詞の扱い
```
"令和5年度の保険"
↓
分割候補:
1. ["令和5年度の", "保険"]
2. ["令和5年度", "の", "保険"]
3. ["令和5年度の保険"]
```

#### 送り仮名のバリエーション
```
"お手続き" vs "お手続"
"お問い合わせ" vs "お問合せ" vs "お問合わせ"
```

## 4. 分割結果の統計分析

### 4.1 フレーズ長の分布
```
1-5文字: 45%    (例: "p34", "iOS", "変更")
6-10文字: 30%   (例: "令和5年度", "保存版")
11-20文字: 20%  (例: "10月25日(水)")
21文字以上: 5%  (例: URL, 長い説明文)
```

```

年度: 10%

その他: 20%
```

## 7. まとめ

現在のフレーズ分割は基本的な区切り文字とパターンマッチングに依存しており、文脈を考慮していないため、アノテーションとの不一致が発生しています。改善には：

1. **短期対策**: パターン定義の拡充とルールの優先順位付け
2. **中期対策**: コンテキストを考慮した分割ロジック
3. **長期対策**: 機械学習ベースの境界検出

が必要です。
