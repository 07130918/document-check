# PDF差分検出システム 総合的問題点分析

## 1. アーキテクチャレベルの問題

### 1.1 差分検出の根本的な設計問題

**現状**: 1つの変更に対して削除・追加・修正の3つを同時に報告
```
例: "令和5年度" → "令和6年度"
報告される差分:
1. DELETION: "令和5年度" → None
2. ADDITION: None → "令和6年度"
3. MODIFICATION: "令和5年度" → "令和6年度"
```

**問題の本質**:
- 差分の「排他性」が考慮されていない
- ユーザーの期待は「1つの変更 = 1つの差分」
- 現在のアプローチは「可能性のある全ての解釈」を報告

### 1.2 文書モデルの欠如

**現状**: テキストを単なるフレーズの集合として扱う
```python
doc1 = {"フレーズ1", "フレーズ2", "フレーズ3"}
doc2 = {"フレーズ1", "フレーズ2'", "フレーズ4"}
```

**問題**:
- 文書の階層構造（見出し、段落、リスト等）が失われる
- 文脈情報が完全に欠落
- 位置情報（ページ、座標）との対応が取れない

## 2. アルゴリズムレベルの問題

### 2.1 フレーズ分割の不整合

**具体例**:
```
アノテーション: "iOS 11/12/13/14/15/16"
システム分割: ["iOS", "11/12/13/14/15/16"]
```

**根本原因**:
1. **分割基準の不明確さ**: 何を「意味の単位」とするかが定義されていない
2. **文脈無視**: 前後の文脈を考慮せずに機械的に分割
3. **ドメイン知識の欠如**: "iOS 11/12/13"が一体として意味を持つという知識がない

### 2.2 集合ベース比較の限界

**現在のアプローチ**:
```python
deleted = set1 - set2  # 順序無視
added = set2 - set1    # 順序無視
```

**問題点**:
1. **順序の喪失**: "A B C" → "C B A"を変更なしと判定
2. **重複の無視**: "A A B" → "A B B"を検出できない
3. **近接性の無視**: 隣接していたフレーズが離れても検出されない

### 2.3 類似度計算の単純さ

**現状**: SequenceMatcherのみに依存
```python
similarity = SequenceMatcher(None, text1, text2).ratio()
```

**不足している観点**:
1. **意味的類似度**: "p34" と "34ページ" の同等性
2. **構造的類似度**: 日付フォーマットの変更
3. **重要度の考慮**: 数字の変更 vs 助詞の変更

## 3. 評価システムの問題

### 3.1 アノテーションとアルゴリズムの不整合

**現状のアノテーション**:
```csv
変更タイプ: "変更"  # 削除/追加/修正の区別なし
```

**アルゴリズムの出力**:
```
DELETION, ADDITION, MODIFICATION  # 3種類に分類
```

**結果**: 構造的に適合率が33.3%を超えられない

### 3.2 評価基準の曖昧さ

**部分一致の問題**:
```python
# どこまでが「正解」か？
"iOS 11/12/13" in "iOS 11/12/13/14/15/16"  # True
"11/12/13" in "iOS 11/12/13/14/15/16"      # True
"S 11/12/" in "iOS 11/12/13/14/15/16"      # True
```

### 3.3 重要度の未考慮

**現状**: すべての差分を同等に扱う

**実際の重要度**:
- 年度変更: 極めて重要
- URL変更: 重要
- 句読点の変更: 低重要度
- 改行位置の変更: ほぼ無視可能

## 4. 実装レベルの問題

### 4.1 処理の非効率性

**現状の処理フロー**:
```
1. 全フレーズを抽出
2. 全組み合わせで類似度計算
3. 閾値以上のペアを全て報告
```

**計算量**: O(n×m) ※n,mはフレーズ数

### 4.2 エラーハンドリングの不足

**現状で考慮されていないケース**:
- 空文書の入力
- 極端に長い文書（メモリ不足）
- 文字エンコーディングの不整合
- PDFからのテキスト抽出失敗

### 4.3 デバッグ情報の不足

**現状**: 最終結果のみ出力

**必要な情報**:
- 各段階での中間結果
- 分割の根拠
- 類似度計算の詳細
- 棄却された候補

## 5. システム設計の問題

### 5.1 モジュール間の結合度

**問題点**:
- PDFTextExtractorとDiffDetectorが密結合
- テキスト正規化が複数箇所に散在
- 評価ロジックがDetector内に混在

### 5.2 拡張性の欠如

**現状で困難な拡張**:
1. 新しい差分タイプの追加
2. 言語別の処理の切り替え
3. ドメイン特化ルールの追加
4. 機械学習モデルの統合

### 5.3 設定の硬直性

**ハードコードされた値**:
- 類似度閾値: 0.5
- フレーズ分割パターン
- 正規化ルール

## 6. 根本的な設計思想の問題

### 6.1 「差分」の定義の不明確さ

**現在の暗黙の前提**:
- テキストの差分 = フレーズ集合の差分
- 1つの変更 = 複数の解釈を許容

**あるべき定義**:
- 差分 = ユーザーが認識する意味的な変更
- 1つの変更 = 1つの最適な解釈

### 6.2 ユースケースの未整理

**想定される用途**:
1. 法的文書のコンプライアンスチェック
2. マニュアルの更新箇所確認
3. 契約書の変更点レビュー

**各用途で求められる精度・粒度が異なる**

## 7. 改善の優先順位

### 7.1 即座に対応すべき問題（1週間以内）

1. **重複差分の抑制**
   ```python
   if modification_detected:
       suppress_deletion_and_addition()
   ```

2. **アノテーション仕様の明確化**
   - 変更タイプの細分化
   - 評価基準の文書化

### 7.2 短期的改善（1ヶ月以内）

1. **フレーズ分割の改善**
   - コンテキスト考慮
   - ドメイン特化パターン

2. **評価システムの再設計**
   - 変更タイプ別評価
   - 重要度別スコアリング

### 7.3 中長期的改善（3ヶ月以内）

1. **アーキテクチャの再設計**
   - 文書モデルの導入
   - プラグイン可能な差分検出器

2. **機械学習の導入**
   - フレーズ境界の学習
   - 変更タイプの自動分類

## 8. 結論

現在のシステムは「テキストの表層的な違い」を検出することはできていますが、「ユーザーが期待する意味的な差分」を提供できていません。根本的な改善には：

1. **差分の定義の明確化**
2. **文書構造の考慮**
3. **評価基準の整合性確保**

が必要です。特に、アノテーション仕様とアルゴリズムの出力を整合させることが、即座の改善につながります。
