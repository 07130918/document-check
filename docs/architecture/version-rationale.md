# 技術スタックバージョン選定の根拠（新規システム）

## 担当分担と選定方針

### 担当分担
- **杉山さん（Webアプリ・インフラ）**: フロントエンド技術、インフラ技術を選定
- **横山さん（Python差分検出）**: バックエンド技術は既存のpyproject.tomlに従う

### 新規システムでの技術選定

#### 1. **フロントエンド技術（杉山さん担当）**

##### Next.js 15
**選定理由**:
- 2025年7月時点での最新安定版
- Turbopack統合による高速ビルド
- React Server Components完全サポート
- 優れた開発者体験とパフォーマンス

##### React 19
**選定理由**:
- React Compiler導入による自動最適化
- Suspenseとエラー境界の改善
- 新しいHooks（useActionState、useOptimistic）
- 長期的なサポートとコミュニティ

##### TypeScript 5.5+
**選定理由**:
- 強力な型システムによる品質保証
- 優れたIDEサポート
- ECMAScript 2024準拠
- チーム開発での生産性向上

#### 2. **バックエンド技術（横山さん担当 - 既存選定済み）**

##### Python 3.11
**選定済み理由**:
- pyproject.tomlで既に選定済み
- 担当者により技術検証・選定完了
- 差分検出エンジンとの互換性確認済み

##### FastAPI（バージョン未指定）
**選定済み理由**:
- 高速なPython Webフレームワーク
- 自動APIドキュメント生成
- 型安全性

#### 3. **インフラ技術（杉山さん担当）**

##### PostgreSQL 16+
**選定理由**:
- 最新のSQL/JSON機能サポート
- 優れたパフォーマンスとセキュリティ
- Azure Database for PostgreSQLでの完全サポート
- 長期的なサポート保証

##### Node.js 22 LTS
**選定理由**:
- 2025年7月時点での最新LTS版
- 長期サポート版（2027年4月まで）
- V8エンジンの最新版による大幅なパフォーマンス向上
- 新しいECMAScript機能のサポート
- セキュリティ強化と最新の脆弱性対策

##### Terraform 1.8+
**選定理由**:
- Infrastructure as Codeのデファクトスタンダード
- Azure Providerの最新機能サポート
- チーム開発での再現性
- 設定の簡素化と可読性

#### 4. **LLM API選定（暫定）**

##### OpenAI API (GPT-4 Turbo)
**選定理由**:
- **日本語性能**: PDF文書の読み順序推定に必要な日本語理解能力が高い
- **API安定性**: 商用利用実績が豊富で安定したサービス提供
- **開発効率**: 豊富なドキュメントとサンプルで迅速な統合が可能
- **コスト効率**: 読み順序推定タスクに対して適切な精度とコストバランス

**代替案検討**:
- **Azure OpenAI Service**: Azureエコシステム統合、データレジデンシー確保
- **Anthropic Claude**: 長文処理能力に優れるが日本語性能を要検証
- **オンプレミスLLM**: セキュリティは高いが初期コストと運用負荷が課題

**今後の方針**:
- プロトタイプでOpenAI APIの精度を検証
- 本格運用時にAzure OpenAI Serviceへの移行を検討
- 使用量とコストを監視し、必要に応じて代替案を評価
