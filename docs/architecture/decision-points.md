# アーキテクチャ設計における判断待ち事項

## 概要
このドキュメントは、アーキテクチャ設計において顧客確認が必要な事項と、その回答による設計への影響をまとめたものです。

## 重要度別の未確定事項

### 🔴 高優先度（設計に大きく影響）

#### 0. クラウドプロバイダー選定（新規追加）
**質問**: クラウドプロバイダーの選定基準や既存環境はありますか？

**影響範囲**:
- インフラ設計全体
- 実装技術の選択
- コスト構造
- 運用体制

**設計オプション**:
- Option A: Azure → 現在の設計案
- Option B: AWS → 最大のエコシステム
- Option C: GCP → 最もコスト効率的

**参考**: [クラウドプロバイダー比較](./cloud-provider-comparison.md)

#### 1. セキュリティ要件（質問No.5）
**質問**: アップロードされるPDFに機密情報が含まれる可能性はありますか？

**影響範囲**:
- ネットワーク設計（プライベートエンドポイントの必要性）
- データ暗号化レベル
- アクセス制御の厳格さ
- コスト（セキュリティ強化により約30%増の可能性）

**設計オプション**:
- Option A: 機密情報なし → 標準的なセキュリティ構成
- Option B: 機密情報あり → プライベートエンドポイント必須、暗号化強化

#### 2. システム稼働率要件（質問No.12）
**質問**: システム稼働率の目標値はありますか？

**影響範囲**:
- 高可用性構成の必要性
- バックアップ・リカバリ戦略
- コスト（高可用性構成で約2倍）

**設計オプション**:
- Option A: 99.5%（月8.76時間） → 単一リージョン構成
- Option B: 99.9%（月43分） → マルチリージョン構成推奨
- Option C: 99.99%（月4.3分） → 完全冗長構成必須

#### 3. 予算規模（質問No.9）
**質問**: 予算規模の目安を教えてください

**影響範囲**:
- インフラ全体のスペック
- 冗長性のレベル
- 監視・運用の充実度

**現在の見積もり**: 月額¥46,500-150,500

### 🟡 中優先度（機能に影響）

#### 4. 差分検出対象（質問No.2）
**質問**: 差分検出の粒度について、以下のどれが必要ですか？
- テキストの追加・削除・変更
- 画像の変更
- 表やグラフの変更
- レイアウトの変更

**影響範囲**:
- PDF処理エンジンの選定
- 処理時間
- 開発工数

**現在の想定**: テキストのみ対応

#### 5. 監視要件（質問No.16）
**質問**: システム監視について以下の要件はありますか？

**影響範囲**:
- Application Insightsの設定
- アラート構成
- 運用コスト

#### 6. 対応ブラウザ（質問No.14）
**質問**: 対応ブラウザとバージョンを教えてください

**影響範囲**:
- フロントエンド実装の複雑度
- テスト工数
- polyfillの必要性

### 🟢 低優先度（詳細設計で対応可能）

#### 7. ログ管理（質問No.13）
**質問**: ログ管理について保存期間・出力項目を教えてください

**影響範囲**:
- ストレージコスト
- Log Analytics設定

**デフォルト案**:
- アプリケーションログ: 30日
- インフラログ: 90日
- セキュリティログ: 180日

#### 8. バックアップ要件（質問No.15）
**質問**: バックアップ・リカバリについて要件はありますか？

**影響範囲**:
- バックアップストレージコスト
- 復旧手順の複雑度

**デフォルト案**:
- データベース: 日次バックアップ、7日保持
- RPO: 24時間、RTO: 4時間

## 段階的な実装アプローチ

### Phase 1: MVP構築
- 最小構成で開始
- セキュリティは標準レベル
- 単一リージョン構成

### Phase 2: 要件に応じた拡張
- セキュリティ強化（必要に応じて）
- 高可用性対応（要件による）
- 監視・運用の充実

### Phase 3: 最適化
- パフォーマンスチューニング
- コスト最適化
- 運用自動化

## 推奨事項

1. **セキュリティファースト**: 機密情報の有無は早期に確認
2. **段階的拡張**: 最初は最小構成で開始し、要件に応じて拡張
3. **コスト透明性**: 各オプションのコスト影響を明確に提示
4. **将来の拡張性**: 後から高可用性やセキュリティ強化が可能な設計

## 次のアクション

1. 高優先度の質問（No.5, 12, 9）の回答を優先的に取得
2. 回答に基づいて設計を確定
3. 中優先度の項目は実装フェーズで詳細化
4. 低優先度の項目はデフォルト値で進行し、必要に応じて調整
