# 改善アプローチの検討レポート

## 概要
タスク1-4の調査結果を踏まえ、PDF差分検出システムの性能要件達成に向けた改善アプローチを検討・評価する。

**更新**: 2025年6月24日、検出率の評価基準を人間アノテーション基準に統一

**性能要件**:
- **🔴 検出率**: 100%（見逃しゼロ）**← 絶対的必須要件・最重要目標**
- **誤検出率**: 10%以下
- **処理時間**: 60ページで2分以内
- **処理能力**: 最大60ページ/100MB
- **検出単位**: 1単語単位（記号、数字含む）

**⚠️ 最重要事項**: 検出率100%の達成が他の全ての要件に優先する絶対条件

---

## 1. 既存AICEからの改善で対応可能な範囲を特定

### 1.1 現状分析
**既存AICE差分検出の現状**:
- **検出率**: 88-90%（要件まで10-12%不足）
- **誤検出率**: 3.2%（要件10%以下を達成済み）
- **処理時間**: 3.6分（要件2分に対し80%超過）
- **アーキテクチャ**: PyMuPDF + Azure AI のハイブリッド構成
- **システム制約**: 同時3ユーザー、1日30回処理想定

### 1.2 既存改善で対応可能な範囲

#### **A. 並列処理による高速化**
**改善内容**:
- 4-8コア並列処理の導入
- マッチング処理の分散実行
- I/O処理とCPU処理の並列化

**ハードウェア制約考慮**:
- **既存環境**: ThreadPoolExecutor（デフォルト4ワーカー）対応済み
- **本番環境**: CPUコア数・スペック未確認（要調査）
- **リスク要因**: 本番環境のCPUコア数が並列処理に不足する可能性
- **対策**: 事前の環境調査・ベンチマークテスト・スケールアップ検討

**期待効果**:
- **処理時間**: 3.6分 → 1.1-1.8分（50-70%短縮）
- **実現確度**: 90%（ハードウェア制約クリア前提）
- **開発期間**: 1-2か月

#### **B. アルゴリズム最適化**
**改善内容**:
- キャッシュ機構の導入（計算結果の再利用）
- インデックス化による検索高速化
- 冗長な計算処理の削除

**期待効果**:
- **処理時間**: 追加20-30%短縮
- **検出精度**: 微向上
- **実現確度**: 85%

#### **C. 閾値・パラメータ調整**
**改善内容**:
- 類似度閾値の最適化（0.8 → 0.75 → 動的調整）
- テキスト正規化処理の強化
- 日本語特化の前処理追加

**期待効果**:
- **アノテーション一致率**: 88-90% → 92-95%（依然として要件100%に未達）
- **誤検出率**: 若干増加（許容範囲内）
- **実現確度**: 95%

#### **D. テキストベース特化最適化**
**改善内容**:
- OCR処理の完全削除
- PyMuPDF直接テキスト抽出の最適化
- 画像処理パイプラインの簡素化

**期待効果**:
- **処理時間**: 80-90%削減（画像ベース比）
- **処理安定性**: 大幅向上
- **実現確度**: 95%

### 1.3 既存改善の限界

#### **技術的制約**
1. **O(n²)計算量**: 総当たり比較の根本的制約
2. **SequenceMatcher精度**: アルゴリズム固有の限界
3. **境界ケース**: 閾値ベース判定の課題
4. **スケーラビリティ**: 60ページ処理時の非線形増加

#### **達成可能範囲**
- **アノテーション一致率**: 最大92-95%（アノテーション一致率100%達成には新規手法必要）
- **処理時間**: 最短0.8-1.4分（要件2分を達成）
- **処理能力**: 60ページ対応可能（分割処理併用）

**結論**: 既存改善だけではアノテーション一致率100%の確実な達成が困難

## 2. 全く別のアプローチ（AI/ML活用等）の必要性再検討

### 2.1 完全一致・類似度一致パターン別の技術アプローチ

#### **完全一致パターン向けアプローチ**

**アプローチ1A: 既存アルゴリズムの完全一致特化改造**
- 既存SequenceMatcherを完全一致モードに変更
- 文字レベル・バイト レベルでの厳密比較
- ハッシュベース高速比較（SHA-256）追加
- PyMuPDF直接テキスト抽出の活用（既存基盤）

**期待性能**:
- **検出率**: 100%
- **処理時間**: 0.5-1.0分
- **誤検出率**: 0%（完全一致のため）
- **実装確度**: 95%

**アプローチ2A: LLM完全一致支援**
- PyMuPDFによる構造化テキスト抽出
- LLMによる文書構造理解・完全一致検証
- 文書フォーマット差異の正規化

**期待性能**:
- **検出率**: 100%（確実）
- **処理時間**: 1.0-1.5分
- **誤検出率**: 0%
- **実装確度**: 90%

#### **類似度一致パターン向けアプローチ**

**アプローチ1B: 既存アルゴリズムの類似度特化改良**
- 既存SequenceMatcherアルゴリズムの最適化
- 日本語特化の前処理・正規化強化
- 動的閾値調整・多段階判定

**期待性能**:
- **検出率**: 88-90% → 92-95%
- **処理時間**: 3.6分 → 0.8-1.4分
- **誤検出率**: 3.2% → 2-5%
- **実装確度**: 90%
- **検出粒度**: 1単語単位対応（記号・数字含む）

**アプローチ2B: LLM意味的類似度判定**
- LLM（GPT-4、Claude-3.5等）による意味的差分検出
- 表記揺れ・文脈理解による高精度判定
- 保険業界特化のプロンプト最適化

**期待性能**:
- **検出率**: 95-98%（LLMの高度な理解力）
- **処理時間**: 1.5-2.5分（API呼び出し含む）
- **誤検出率**: 1-3%（意味的理解による精緻化）
- **実装確度**: 85%（LLM依存のリスク）

### 2.2 パターン別推奨戦略

#### **完全一致パターンの場合**

**推奨**: アプローチ1A（テキストベース完全一致）を主軸
- **理由**: 100%確実な検出率達成、高速処理、低コスト
- **補完**: アプローチ2A（LLM支援）で文書構造差異を正規化
- **アンサンブル**: 不要（完全一致は明確な判定基準）

#### **類似度一致パターンの場合**

**推奨**: アプローチ1B + 2B のアンサンブル統合
- **理由**: 検出率100%達成にはLLMの意味的理解が必要
- **戦略**: テキスト特化（高速・安定）+ LLM（高精度）の相互補完

**アンサンブル統合方式**:
- **1次判定**: アプローチ1B（高速スクリーニング）
- **2次判定**: アプローチ2B（詳細意味的検証）
- **最終判定**: 信頼度重み付け統合

### 2.3 要件パターン別実装戦略

#### **完全一致要件の場合（推奨：シンプル戦略）**

**Phase 1**: アプローチ1A実装（7月第1-2週）
- テキストベース完全一致実装
- ハッシュベース高速化
- **目標**: 検出率100%、処理時間0.5-1.0分

**Phase 2**: 最適化・統合（7月第3-4週）
- 大容量処理対応・並列化
- 既存システム統合・テスト
- **目標**: 全要件確実達成

**Phase 1**: 両アプローチ並行開発（7月第1-3週）
- アプローチ1B: テキスト特化改良
- アプローチ2B: LLM意味的判定
- 各々独立評価・ベンチマーク

**Phase 2**: アンサンブル統合（7月第4週〜8月第2週）
- 統合アルゴリズム開発
- 重み付け最適化・信頼度調整
- **目標**: 検出率99-100%達成
