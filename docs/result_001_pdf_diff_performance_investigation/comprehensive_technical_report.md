## 1. 調査背景と目的

### 1.1 読み順序推定技術の変更背景

#### **従来の位置ベースソートの課題**
既存システムはmeiji-document-checkの3.2px閾値による単純な位置情報ソートを使用していましたが、以下の重要な課題が明確になりました：

```
従来方式の問題例:
• 斜め文字: 文章が斜めを向いている場合の座標処理困難
• フォントサイズ差: 大きなフォントと小さなフォントの行判定誤り  
• 複雑レイアウト: 表構造、カラムレイアウトでの順序混乱
```

#### **LLM中心型読み順序推定への移行理由**
1. **文脈理解能力**: LLMによる文書構造の意味的理解
2. **視覚的理解**: PDFページ画像からの直接的レイアウト認識
3. **業務要件の適合**: 複雑な文書レイアウトへの高精度対応

### 1.2 性能要件（混同行列ベース定義・単語ベース対応）

#### **基本性能要件**
```
混同行列による評価基準（単語ベース）:
                     | アノテーション=変更 | アノテーション=非変更 |
アルゴリズム=変更検出  |    真陽性(TP)      |    偽陽性(FP)      |
アルゴリズム=変更なし  |    偽陰性(FN)      |    真陰性(TN)      |
```

- **真陽性率（感度・検出率）**: 100%（TP/(TP+FN) = 100%）単語レベル変更の見逃しゼロ
- **偽陰性率（見逃し率）**: 0%（FN/(TP+FN) = 0%）単語レベル変更の見逃しゼロ
- **偽陽性率（誤検出率）**: 10%以下（FP/(FP+TN) ≤ 10%）不要確認削減
- **真陰性率（特異度）**: 90%以上（TN/(FP+TN) ≥ 90%）正常判定精度
- **処理時間**: 60ページで2分以内
- **処理能力**: 最大60ページ/100MB
- **検出単位**: **1単語単位**（記号、数字含む）← **重要な要件**

#### **ラベル別詳細要件（混同行列ベース・単語ベース）**
- **追加単語**: 真陽性率100%、偽陽性率10%以下
- **削除単語**: 真陽性率100%、偽陽性率10%以下
- **修正単語**: 真陽性率100%、偽陽性率10%以下
- **ラベル分類精度**: 95%以上

        "word_level_change": True,  # 単語「100,000」→「200,000」は完全に異なる
        "business_impact": "高"     # 金額変更は業務上極めて重要

## 3. LLM中心型読み順序推定システムの技術的実現可能性

### 3.1 LLM中心型読み順序推定の技術アプローチ

#### **アプローチ1: 人間が読む順番に並び替える**

**ステップ1: 入力データ統合**
- PDFページ画像 + レイアウト構造情報 + テキスト座標情報を1つのプロンプトに統合
- アノテーション済みサンプルを参考例として提示

**ステップ2: LLM推論実行**
- 文書知識の活用: 「第1条→第2条」「上記の通り→下記参照」等のパターン認識
- 視覚的理解: PDFページ画像から表・カラム・図表の配置を理解
- 論理的推論: 文脈のつながりを考慮した読み順序決定

**ステップ3: 品質チェックと改善**
- 自己評価: LLMが推定結果の自然さを数値評価（1-10点）
- 低品質判定時: 代替案を自動生成して再評価
- 最適解選択: 最も自然な読み順序を最終出力

**ステップ4: 長文書対応**
- ページ単位処理: 各ページを個別に読み順序推定
- 文脈継承: 前ページの読み順序パターンを次ページに活用
- 階層処理: ページ全体→段落→文章→単語の順で段階的に処理

**期待性能:**
- 読み順序精度: 95-98%（LLM文脈理解による大幅改善）
- 処理時間: 1.0-1.5分（60ページ、Azure AI + LLM統合）
- 実現確度: 90%
- 開発期間: 1週間

#### **アプローチ2: 順番並び替え後の完全一致アルゴリズム**

**前処理（正規化）**
- 文字正規化: 全角半角統一、Unicode正規化、空白文字統一
- 意味保持正規化: 改行文字統一、連続空白の単一空白化、句読点統一

**意味単位認識**
- パターンベース認識: 日付パターン、金額パターン、制度情報
- 結合処理: 認識されたパターン内の単語を結合し単一の意味単位として処理

**差分検出エンジン**
- 階層的比較: 意味単位レベル → 単語レベル → 文字レベルの段階的比較
- SequenceMatcher適用: 完全一致以外を差分候補として抽出
- 後処理フィルタ: 除外ルール適用（表記揺れパターン）

**期待性能:**
- 真陽性率: 99-100%（完全一致による確実な検出）
- 処理時間: 0.5-1.0分（60ページ、正規化+SequenceMatcher処理）
- 実現確度: 95%
- 開発期間: 2-3週間

#### **アプローチ3: 統合システム（読み順序推定 + 差分検出）**

**統合処理フロー**
- Phase 1: LLM中心型読み順序推定による文章の自然な並び替え
- Phase 2: 並び替え後テキストに対する完全一致差分検出
- Phase 3: 意味単位認識による適応的単位設定
- Phase 4: 最終結果の品質チェックと出力

**期待性能:**
