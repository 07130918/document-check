# PDF差分検出技術調査レポート

## 1. 商用ソリューション

### Adobe Acrobat Pro DC
- **機能**: PDF比較、マークアップ、注釈
- **技術仕様**:
  - テキスト差分、画像差分、フォーマット差分を検出
  - OCR機能による画像内テキスト比較
- **性能指標**:
  - 処理速度: 約10-50ページ/分（文書により変動）
  - 検出精度: テキスト変更95%以上、レイアウト変更85%程度
- **制限事項**:
  - 暗号化PDFでは制限あり
  - 複雑なレイアウトでは誤検出が発生
- **メリット（本要件での評価）**:
  - 商用実績豊富で安定性が高い
  - GUI提供により結果確認が容易
- **デメリット（本要件での評価）**:
  - **検出率95%で要件100%に未達**
  - **処理速度が遅く60ページ2分要件に不適合**
  - **画像・スキャンPDF対応により処理負荷増大**
  - ライセンス費用が高額
  - API統合が困難
- **テキストベース特化時の評価**:
  - テキスト抽出機能のみ使用すれば高速化可能
  - ただし商用ツールとして過機能

### DiffPDF
- **機能**: ページ単位比較、文字・単語レベル差分
- **技術仕様**:
  - ピクセルベース比較とテキストベース比較の併用
  - Qt frameworkベース
- **性能指標**:
  - 処理速度: 約20-100ページ/分
  - 検出精度: テキスト変更90%以上
- **制限事項**:
  - 大容量ファイルでメモリ使用量が増大
  - 画像の微細な変更は検出困難
- **メリット（本要件での評価）**:
  - **処理速度が比較的高速で60ページ2分要件に適合可能**
  - オープンソースで導入コストが低い
- **デメリット（本要件での評価）**:
  - **検出率90%で要件100%に大幅未達**
  - **ピクセルベース比較により処理時間増大**
  - 画像差分検出精度が不十分
- **テキストベース特化時の評価**:
  - テキストベース比較のみ使用で大幅高速化
  - ピクセル比較スキップにより要件内処理可能

## 2. オープンソースライブラリ

### pdf-diff (Python)
- **技術仕様**: PDFMinerベース、テキスト抽出後diff実行
- **処理方式**: テキストベース差分検出
- **性能**: 軽量だが画像・レイアウト変更は検出不可
- **メリット（本要件での評価）**:
  - **軽量で高速処理、60ページ2分要件に適合**
  - Pythonで実装しやすい
  - テキスト差分は高精度
  - **テキストベース特化で最適**
- **デメリット（本要件での評価）**:
  - 画像・レイアウト差分未対応（本件では問題なし）
  - 機能が限定的だが要件には十分

### diff-pdf (C++)
- **技術仕様**: Poppler libraryベース
- **処理方式**: ページ画像化後ピクセル差分検出
- **性能**: 高速だがテキスト構造は無視
- **メリット（本要件での評価）**:
  - **高速処理で60ページ2分要件に適合**
  - 視覚的差分は確実に検出
  - C++による高パフォーマンス
- **デメリット（本要件での評価）**:
  - **ページ画像化処理により時間増大**
  - **テキスト構造無視で100%検出不可**
  - 誤検出率が高い可能性
  - 意味的差分を判定できない
- **テキストベース特化時の評価**:
  - 画像化処理が不要なため本件には不適合
  - テキストベース処理の方が効率的

### PyMuPDF (fitz)
- **技術仕様**: MuPDFライブラリのPythonバインディング
- **機能**: テキスト抽出、画像抽出、描画情報取得
- **特徴**: 高速処理、詳細な構造情報取得可能
- **備考**: meijiでも使われている，現在の標準的手法
- **メリット（本要件での評価）**:
  - **高速処理で60ページ2分要件に適合**
  - **テキストベース特化で最適な性能**
  - 既存実績あり（meiji採用）
  - Pythonで実装容易
  - 画像処理機能もあるが本件では不使用
- **デメリット（本要件での評価）**:
  - 差分検出ロジック自体は別途実装必要
  - 日本語処理の複雑性
- **テキストベース特化時の優位性**:
  - **既存AICEで採用済み**で実装ノウハウあり
  - テキスト抽出のみ使用で大幅高速化
  - 画像・OCR処理スキップで処理負荷軽減

## 3. 外部APIサービス

### PDF API services (比較機能付き)
- **DocumentCloud API**: テキスト比較機能
- **PDFShift API**: レンダリング比較
- **制限**: プライバシー、コスト、通信依存の課題
- **メリット（本要件での評価）**:
  - 実装工数削減
  - 高品質なAPIサービス
- **デメリット（本要件での評価）**:
  - **通信時間で60ページ2分要件達成困難**
  - 機密文書のプライバシーリスク
  - 継続的なAPI費用発生
  - **検出率100%の保証なし**
  - **画像処理機能により処理時間増大**
- **テキストベース特化時の評価**:
  - テキスト比較APIのみ使用すれば高速化可能
  - ただし通信オーバーヘッドは残存

## 4. AI/ML活用アプローチ

### Computer Vision手法
- **技術**: OpenCV、PIL、scikit-image
- **処理方式**: 画像差分検出、輪郭検出、特徴点マッチング
- **可能性**: レイアウト変更の高精度検出
- **メリット（本要件での評価）**:
  - 視覚的差分の検出可能
  - 画像処理技術の活用
- **デメリット（本要件での評価）**:
  - **PDF画像化処理で大幅な時間増加**
  - **テキスト内容の意味的変更検出不可**
  - 誤検出率が高くなる傾向
  - 微細な変更での過敏反応
- **テキストベース特化時の評価**:
  - **本件では不要**（画像処理コストのみでメリットなし）
  - テキスト処理に特化した方が効率的

### NLP手法
- **技術**: BERT、sentence-transformers
- **処理方式**: 意味的差分検出、文書構造解析
- **可能性**: 内容の実質的変更検出
- **メリット（本要件での評価）**:
  - **日本語テキストの高精度差分検出**
  - 意味的変更の検出
  - **テキストベース特化で高速処理**
  - LLM活用により60ページ2分要件達成可能
- **デメリット（本要件での評価）**:
  - 画像・レイアウト差分未対応（本件では問題なし）
  - モデル実行コスト
  - API依存による安定性懸念
- **テキストベース特化時の評価**:
  - **画像処理不要で大幅高速化**
  - テキスト抽出が直接可能なため処理負荷軽減
  - NLP処理に計算資源を集中投入可能

## 5. 技術的実現可能性評価

### 検出率100%要件
- **現実的評価**: **条件付きで可能**
- **条件**: テキスト抽出可能なPDFのみを対象
- **理由**:
  - テキストベースPDFでは構造が明確
  - OCR処理の不確実性を排除
  - スキャンPDF等の画像処理複雑性を除外
- **目標**: 100%検出率（見逃しゼロ）

### 誤検出率10%以下
- **現実的評価**: **達成可能**
- **アプローチ**: 複数手法組み合わせ、閾値調整

### 処理時間60ページ2分以内
- **現実的評価**: **達成可能**
- **前提**: テキストベースPDFのみ（OCR処理なし）
- **技術**: 高速テキスト抽出 + 効率的差分検出 + 並列処理
- **画像ベース対応時のデメリット**: OCR処理により処理時間増加

### 処理能力60ページ/100MB
- **現実的評価**: **達成可能**
- **前提**: テキスト抽出可能PDF
- **要件**: 適切なアルゴリズム選択、並列処理実装

## 7. 結論

### テキストベースPDF特化の優位性

**テキスト抽出可能PDF限定**であれば、現在の技術水準で**全ての性能要件が技術的に実現可能**と判断。

#### 主要な優位性
1. **処理時間の大幅短縮**: 既存アプローチの類似度計算ボトルネックを解決
2. **検出精度の向上**: テキスト構造が明確で100%検出率達成可能
3. **システム安定性**: 画像処理の不確実性を排除
4. **開発・運用コスト削減**: 複雑な画像処理機能が不要

#### 画像ベース対応時の制約
- **処理時間**: OCR処理により60ページ2分要件の達成が困難（既存は類似度計算がボトルネック）
- **検出精度**: スキャン品質により検出率にばらつき
- **システム複雑性**: 画像処理とテキスト処理の両立が必要

**本件要件では画像ベースPDF対応が不要のため、テキストベース特化により最適な性能が実現可能。**
