# PDF解析アルゴリズムについて (About PDF Analysis Algorithm)

このドキュメントでは、文書チェックシステムで使用されているPDF解析アルゴリズムの詳細について説明します。

## 概要

本システムは、保険関連文書のPDF解析に特化した高度なアルゴリズムを実装しており、クリーンアーキテクチャに基づいて設計されています。主にPyMuPDFとAzure AI Document Intelligenceを組み合わせて、高精度な文書解析を実現しています。

## 1. 使用技術・ライブラリ

### 主要ライブラリ
- **PyMuPDF (fitz)** v1.23.8: PDF解析・操作の中核ライブラリ
- **Azure AI Form Recognizer** v3.3.3: クラウドベースOCRサービス
- **Python-Levenshtein** v0.23.0: テキスト類似度計算
- **NumPy** v1.26.3: バウンディングボックス計算用配列操作

### アーキテクチャ構成
```
Infrastructure Layer → Domain Layer ← Application Layer
```

- **Domain Layer**: OCRインターフェース、PDF保存抽象化
- **Application Layer**: PDF処理ラッパー、ファイルアップロード用途
- **Infrastructure Layer**: Azure AI Document Intelligence実装、Azure Blob Storage

## 2. PDF テキスト抽出ワークフロー

### ステップ1: 文書読み込み
- PyMuPDF (`fitz.open()`) を使用してPDFを読み込み
- Azure Blob StorageまたはローカルストレージからPDFProcessor.get_fitz_doc()で取得

### ステップ2: ページ処理戦略
- 見開きレイアウトを想定した左右ページ分割処理
- ページインデックス計算: `左ページ = page_index * 2 - 1`, `右ページ = page_index * 2`
- 表紙（1ページ目）は通常スキップ

### ステップ3: テキスト抽出手法

システムは2つの補完的なアプローチを使用：

#### A. PyMuPDF ネイティブ抽出 (`PDFTextExtractLogicDomainService`)
- `page.get_text("dict")` による構造化テキスト抽出（位置情報付き）
- 並列処理（デフォルト4ワーカー）
- バッチ処理による性能最適化（バッチサイズ: 100アイテム）
- 高度なフォント解析とサイズベースフィルタリング

#### B. Azure AI Document Intelligence OCR (`AzureIntelligencePDFOCRImpl`)
- `DocumentAnalysisClient` の "prebuilt-read" モデルを使用
- 信頼度スコアと精密ポリゴン座標付きテキスト抽出
- 手書きテキスト検出対応
- ページ、行、単語、バウンディングボックスの構造化JSON出力

## 3. 高度なテキスト処理機能

### フォントメトリクス解析
- `FontMetrics.from_sizes()` による動的フォントサイズ閾値計算
- フォントサイズ vs ブロック幅比較による縦書きテキスト検出
- サイズベーステキストフィルタリング（設定可能な1170px境界フィルタ）

### テキスト位置とバウンディングボックス
- `BBox` オブジェクトによる精密座標抽出（左上、右下ポイント）
- 相対座標（0-1範囲）正規化サポート
- Azure OCR結果のポリゴン-バウンディングボックス変換

### 保険プラン種別検出
- Levenshtein距離ベーステキストマッチング（デフォルト閾値: 0.8）
- プラン名認識のフォントサイズ検証（≥20pxまたは動的閾値以上）
- 会社固有プランマッピング統合

## 4. PDF差分解析アルゴリズム

### 解析手順 (`PdfDiffLogicDomainService`)
1. 両文書からテキストとバウンディングボックスを抽出
2. `SequenceMatcher.ratio()` によるテキスト類似度マッチング
3. 閾値ベースマッチング（0.8類似度）
4. 差分の視覚的ハイライト（赤色矩形）
5. 3カテゴリ分類: 旧文書固有、新文書固有、変更内容

### 視覚化
- 差分に対する赤色矩形オーバーレイ
- 座標ベース精密ハイライト
- 各年度の差分用個別出力文書

## 5. 文書検証・チェックロジック

### 多段階検証
1. **厳密テキストマッチング**: 完全文字列比較
2. **部分マッチング**: Levenshtein距離ベース類似度
3. **集約ルール**: ページレベル・文書レベルテキスト集約
4. **近接チェック**: コンテキスト用近傍テキスト検証

### 外部データ統合
- 会社固有外部データマッピング
- プラン種別分類・検証
- 外部データセットに基づく動的テキスト置換

## 6. ストレージ・ファイル管理

### デュアルストレージサポート
- **Azure Blob Storage**: 本番クラウドストレージ（接続文字列設定）
- **Local Storage**: 開発・テスト用ファイルシステムアクセス
- 抽象インターフェース (`IPDFStorage`) によるシームレス切り替え

### ファイル操作
- メモリ効率のための `BytesIO` ストリームベース処理
- 大容量ファイルサポート（最大500MB）
- タイムスタンプベース組織化による自動ファイルパス生成

## 7. 性能最適化

### 並列処理
- 同時ページ処理用 `ThreadPoolExecutor`
- 設定可能ワーカー数（デフォルト: 4）
- 最適メモリ使用のためのタスクバッチング

### メモリ管理
- ストリームベース文書処理
- バッチテキスト処理（バッチあたり100アイテム）
- min/max演算を使用した効率的バウンディングボックス計算

### キャッシュ・フィルタリング
- オプション1170px境界フィルタリング
- ページごとフォントメトリクスキャッシュ
- 重複bbox除去ユーティリティ

## 8. エラー処理・復旧性

### 堅牢なPDF変換
- 2段階PDF保存アプローチ（デフォルトオプション → クリーンアップオプション）
- 破損文書用ガベージコレクション
- 問題PDFのコンテンツストリーム無害化

### リトライメカニズム
- 指数バックオフ付きデータベース操作
- 多段階プロセス用トランザクション管理
- パイプライン全体の包括的エラーロギング

## 9. 統合ポイント

### ユースケース統合
- 自動PDF解析付きファイルアップロード処理
- 結果生成付き検査ワークフロー
- 多形式出力（注釈付きPDF、Excelレポート）

### フロントエンド統合
- 文書表示用React-PDFコンポーネント
- 座標マッピング付きPDF注釈サポート
- 長時間実行操作のリアルタイム進捗追跡

## 10. アルゴリズムの特徴

### 高精度テキスト抽出
- ネイティブPDF解析とクラウドOCRの組み合わせ
- フォント解析による高度なテキスト分類
- 位置情報保持による精密な差分検出

### スケーラブル処理
- 並列処理による高速化
- バッチ処理によるメモリ効率化
- 大容量ファイル対応

### 柔軟な検証ロジック
- 複数の類似度計算手法
- 段階的マッチング戦略
- 外部データとの動的統合

本システムは、従来のPDF解析と最新のクラウドベースOCRを組み合わせた高度なPDF解析プラットフォームであり、保険書類処理ワークフローのための包括的な文書検証、差分解析、自動チェック機能を提供します。
