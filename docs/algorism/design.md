# PDF差分検出システム アルゴリズム要件定義

## 1. システム概要

### 1.1 目的
PDF文書の差分検出を自動化し、契約書・仕様書・ガイドラインなどの重要文書の変更確認作業を効率化する。

### 1.2 解決すべき課題
- 手作業による文書比較の時間的コスト
- ヒューマンエラーによる重要な変更の見落とし
- 一文字・数値違いによる重大な影響の回避
- 複雑なレイアウトでの読み順序の混乱

### 1.3 性能要件
- **検出率**: 100%（見逃しゼロ）
- **誤検出率**: 10%以下
- **処理時間**: 60ページで2分以内
- **処理容量**: 最大60ページ/100MB

## 2. 核心アルゴリズム要件

### 2.1 LLM中心型読み順序推定システム

#### 2.1.1 要件背景
- 従来の位置ベース（3.2px閾値）ソートでは複雑レイアウト対応が困難
- 斜め文字・表構造・カラムレイアウトで順序混乱が発生
- 人間の自然な読み順序に沿った文書理解が必要

#### 2.1.2 技術要件
- **入力**: PDF文書のテキストブロック座標情報
- **処理**: LLMによる文脈理解に基づく読み順序推定
- **出力**: 自然な読み順序でソートされたテキストシーケンス
- **精度**: アノテーター間一致率95%以上

#### 2.1.3 実装制約
- LLM API利用に関するセキュリティ制約の考慮
- 機密情報の外部送信制限への対応
- API コスト・レスポンス時間の最適化

### 2.2 単語ベース差分検出アルゴリズム

#### 2.2.1 要件背景
- 文字ベース類似度（SequenceMatcher）では重要変更を見逃し
- 金額「100,000円→200,000円」（類似度88.9%）等の検出困難
- 業務上重要な数値・日付変更の確実な検出が必要

#### 2.2.2 技術要件
- **トークン化**: MeCabによる単語単位での文書分割
- **アノテーション前提**: 差分アノテーションは文章単位で入力される想定
- **セマンティック理解**: 類義語・同義語の区別
- **変更分類**: 追加・削除・修正の3カテゴリ分類

#### 2.2.3 検出アルゴリズム
1. **前処理**: 文書の正規化・ノイズ除去
2. **文章分割**: アノテーション単位（文章単位）での分割
3. **単語分割**: MeCabによる形態素解析トークン化
4. **アライメント**: 対応する文書構造の対応付け
5. **差分計算**: 編集距離による変更検出
6. **後処理**: 誤検出除去・結果統合

### 2.3 アンサンブル統合システム

#### 2.3.1 統合戦略
- **PyMuPDF**: 高速PDF解析・構造抽出
- **Azure AI Document Intelligence**: OCR・レイアウト解析
- **LLM**: 読み順序推定・文脈理解
- **統計的手法**: 類似度計算・閾値判定

#### 2.3.2 並列処理最適化
- **ThreadPoolExecutor**: CPU集約タスクの並列化
- **メモリ管理**: 大容量ファイルでのメモリ効率化

## 3. 機能要件

### 3.1 入力処理
- **ファイル形式**: PDF（テキストベースのみ対応）
- **文字エンコーディング**: UTF-8、Shift_JIS対応
- **ファイルサイズ**: 最大100MB
- **ページ数**: 最大60ページ

### 3.2 差分検出機能
- **変更タイプ**: 追加・削除・修正
- **検出粒度**: 文字・単語・文・段落・ページレベル
- **信頼度**: 検出結果の信頼度スコア付与

### 3.3 出力機能
- **可視化**: 差分箇所のハイライト表示
- **注釈**: 変更内容の詳細説明（追加・削除・修正）
- **レポート**: 変更サマリー・統計情報
- **エクスポート**: 注釈付きPDF・CSV形式

## 4. 非機能要件

### 4.1 性能要件
- **レスポンス時間**: 60ページで2分以内
- **スループット**: 同時3ユーザー処理
- **メモリ使用量**: 1GB以下/プロセス
- **CPU使用率**: 80%以下維持

### 4.2 精度要件
- **真陽性率（検出率）**: 100%（False Negative = 0）
- **偽陽性率（誤検出率）**: 10%以下

### 4.3 安定性要件
- **エラー処理**: 異常PDF・破損ファイルへの対応
- **メモリリーク**: 長時間稼働でのメモリ安定性
- **並行処理**: デッドロック・競合状態の回避

## 5. 技術制約・前提条件

### 5.1 技術制約
- **LLM API**: 外部API依存によるレイテンシ・コスト制約
- **OCR精度**: 手書き文字・低品質画像での制限
- **メモリ制約**: 大容量PDF処理時のメモリ制限

### 5.2 前提条件
- **文書品質**: 読み取り可能な品質のPDF
- **言語**: 日本語文書を主対象
- **レイアウト**: 一般的なビジネス文書形式

## 6. 検証・評価方法

### 6.1 定量評価
- **ベンチマークデータセット**: 既知の差分データによる評価
- **A/Bテスト**: 従来手法との比較評価
- **パフォーマンステスト**: 処理時間・メモリ使用量測定

### 6.2 定性評価
- **専門家レビュー**: 法務・契約専門家による評価
- **ユーザビリティテスト**: 実際のユーザーによる使用性評価
- **誤検出分析**: False Positive/Negative の詳細分析
