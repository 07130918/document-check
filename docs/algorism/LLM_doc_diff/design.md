# PDF差分検出システム アルゴリズム要件定義

## 1. システム概要

### 1.1 目的
PDF・Word・Pptx文書の差分検出を自動化し、契約書・仕様書・ガイドラインなどの重要文書の変更確認作業を効率化する。

### 1.2 解決すべき課題
- 手作業による文書比較の時間的コスト
- ヒューマンエラーによる重要な変更の見落とし
- 一文字・数値違いによる重大な影響の回避
- 複雑なレイアウトでの読み順序の混乱

### 1.3 性能要件
- **検出率**: 99-100%（見逃しゼロ）
- **誤検出率**: 10%以下
- **処理時間**: 5分以内（ファイルサイズに関わらず）
- **処理容量**: 最大100ページ/40MB

## 2. 核心アルゴリズム要件

### 2.1 Bounding Box ベース読み順序推定システム（文章単位）

#### 2.1.1 要件背景
- 従来の位置ベース（3.2px閾値）ソートでは複雑レイアウト対応が困難
- 斜め文字・表構造・カラムレイアウトで順序混乱が発生
- 人間の自然な読み順序に沿った文書理解が必要
- **重要**: 読み順序は文章単位で推定する必要がある

#### 2.1.2 技術要件
- **入力データ型**: `bbox_text_data_list : list[bbox_text_data]`
  - `bbox_text_data`: {"bbox": [x, y, width, height], "text": "単語", "page": int}
  - textは単語単位で分割されたもの
- **処理**: 
  - 単語単位のbbox_text_dataを文章単位にグルーピング
  - 文章単位での読み順序推定（文章の代表座標を使用）
  - ページ内の読み順序を座標情報から推定
  - 左上から右下への自然な読み順序でソート
- **出力**: 文章単位で読み順序がソートされた文書

#### 2.1.3 実装方針
- アノテーションは使用せず、座標ベースの読み順序推定
- ページ単位での処理により大規模文書にも対応
- 読み順序の可視化のためのハイライト機能
- **文章抽出の課題**: 現状では単語から文章へのグルーピングが不完全なため、評価時に考慮が必要

### 2.2 Bounding Box 単語ベース差分検出アルゴリズム（単語単位）

#### 2.2.1 要件背景
- 文字ベース類似度（SequenceMatcher）では重要変更を見逃し
- 金額「100,000円→200,000円」（類似度88.9%）等の検出困難
- 業務上重要な数値・日付変更の確実な検出が必要

#### 2.2.2 技術要件
- **入力**: bbox_text_data_listから構築された単語リスト
- **処理単位**: 単語単位での差分検出（既に分割されたbbox_text_dataを使用）
- **アノテーション**: 使用しない（出力で視覚的に確認）
- **変更分類**: 追加・削除・修正の3カテゴリ分類
- **位置情報保持**: 差分検出時もbbox情報を保持
- **重要**: 差分検出は必ず単語単位で実施し、細かい変更も検出可能にする

#### 2.2.3 検出アルゴリズム
1. **前処理**: bbox_text_dataの正規化・ノイズ除去
2. **ページ単位処理**: forループで1ページずつ処理
3. **単語マッチング**: bbox位置と単語内容でマッチング（単語単位）
4. **差分計算**: 編集距離とbbox位置による変更検出（単語単位）
5. **差分位置記録**: 変更があった単語のbbox情報を記録
6. **後処理**: 誤検出除去・結果統合

### 2.3 アンサンブル統合システム

#### 2.3.1 統合戦略
- **PyMuPDF**: 高速PDF解析・構造抽出
- **python-docx/python-pptx**: Word/Pptxファイル解析
- **Azure AI Document Intelligence**: OCR・レイアウト解析
- **LLM**: 読み順序推定・文脈理解
- **統計的手法**: 類似度計算・閾値判定

#### 2.3.2 並列処理最適化
- **ThreadPoolExecutor**: CPU集約タスクの並列化
- **メモリ管理**: 大容量ファイルでのメモリ効率化

## 3. 機能要件

### 3.1 入力処理
- **ファイル形式**: PDF・Word・Pptx（優先順位: PDF > Word > Pptx）
- **文字エンコーディング**: UTF-8、Shift_JIS対応
- **ファイルサイズ**: 最大40MB
- **ページ数**: 最大100ページ

### 3.2 差分検出機能
- **変更タイプ**: 追加・削除・修正
- **検出粒度**: 文字・単語・文・段落・ページレベル
- **信頼度**: 検出結果の信頼度スコア付与

### 3.3 出力機能
- **可視化**: 
  - 読み順序のハイライト（番号付き）
  - 差分箇所のハイライト（色分け：追加=緑、削除=赤、修正=黄）
- **出力ファイル形式**:
  - PDF: 元ファイルにハイライトを追加
  - Word(DOCX): 元ファイルにハイライトを追加
  - PowerPoint(PPTX): 元ファイルにハイライトを追加
- **評価方法**: 出力ファイルを人力で確認し、評価
  - 読み順序の正確性
  - 差分検出の正確性
  - 誤検出・見逃しの確認

## 4. 非機能要件

### 4.1 性能要件
- **レスポンス時間**: 5分以内（ファイルサイズに関わらず）
- **スループット**: 同時3ユーザー処理
- **メモリ使用量**: 2GB以下/プロセス
- **CPU使用率**: 80%以下維持

### 4.2 精度要件
- **真陽性率（検出率）**: 99-100%（False Negative ≒ 0）
- **偽陽性率（誤検出率）**: 10%以下

### 4.3 安定性要件
- **エラー処理**: 異常PDF・破損ファイルへの対応
- **メモリリーク**: 長時間稼働でのメモリ安定性
- **並行処理**: デッドロック・競合状態の回避

## 5. 技術制約・前提条件

### 5.1 技術制約
- **LLM API**: 外部API依存によるレイテンシ・コスト制約
- **OCR精度**: 手書き文字・低品質画像での制限
- **メモリ制約**: 大容量ファイル処理時のメモリ制限
- **ファイル形式制約**: Word/Pptxの複雑なレイアウトやオブジェクト配置の処理

### 5.2 前提条件
- **文書品質**: 読み取り可能な品質のファイル
- **言語**: 日本語文書を主対象
- **レイアウト**: 一般的なビジネス文書形式
- **ファイル形式**: テキストベースのPDF・Word・Pptx（画像PDFはOCR処理が必要）

## 6. 検証・評価方法

### 6.1 人力評価方法
- **評価対象**: 出力されたハイライト付きファイル（PDF/DOCX/PPTX）
- **評価項目**:
  1. **読み順序の正確性（文章単位）**:
     - 番号付きハイライトが文章単位で自然な読み順序になっているか
     - 複雑なレイアウト（表、カラム）での順序の妥当性
     - 文章抽出の不完全さを考慮した評価
  2. **差分検出の正確性（単語単位）**:
     - 追加（緑）・削除（赤）・修正（黄）の正しさ（単語単位）
     - 重要な変更（金額、日付、数値）の検出率
     - 誤検出の頻度と種類
- **評価プロセス**:
  1. システムが生成したハイライト付きファイルを確認
  2. 元の2ファイルと比較して正確性を検証
  3. 評価シートに結果を記録

### 6.2 パフォーマンス評価
- **処理時間**: ファイルサイズ別の処理時間測定
- **メモリ使用量**: 大規模ファイルでのメモリ消費
- **並列処理効率**: 複数ファイル同時処理時の性能

### 8.2 優先要件
