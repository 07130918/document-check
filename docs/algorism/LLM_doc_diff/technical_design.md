# 文書差分検出システム 技術設計書

## 1. システムアーキテクチャ

### 1.1 全体構成

本システムは、Frontend（Next.js）、Backend（FastAPI）、外部API（LLM、Azure）の3層構造で構成されます。BackendはSQL Serverデータベースと連携し、文書の解析結果や差分検出結果を永続化します。

### 1.2 Clean Architecture適用

システムは以下の層に分離されています：
- **Domain Layer**: PDF差分検出ビジネスロジック
- **Application Layer**: ユースケース実行・DTO変換
- **Infrastructure Layer**: 外部システム統合・永続化

## 2. 核心コンポーネント設計

### 2.1 文書解析エンジン (DocumentAnalysisEngine)

#### 2.1.1 責務
文書解析エンジンは、PDF・Word・PowerPointファイルの統合解析を担当します。各文書からbbox_text_data形式でのデータ抽出、文書構造・座標情報の抽出、レイアウト解析・単語単位のテキスト識別を行います。

#### 2.1.2 技術仕様
DocumentAnalysisEngineは、ファイルタイプに応じて適切なサービスを選択し、BBox情報を抽出します。処理の優先順位は以下の通りです：

1. Azure Document Intelligence（ネイティブ抽出と併用で飼養する）
2. ネイティブ抽出（PyMuPDF、python-docx、python-pptx）
3. PDF変換経由での抽出（Word/PowerPoint）

スキャンされたPDFなどOCRが必要な文書は自動的に検出され、Azure Document Intelligenceにフォールバックします。

#### 2.1.3 パフォーマンス最適化
- **メモリ効率**: ページ単位での遅延読み込み
- **並列処理**: ThreadPoolExecutorによるページ並列解析
- **キャッシュ**: 解析結果の一時保存

### 2.2 読み順序推定システム (ReadingOrderEstimator)

#### 2.2.1 座標ベース推定戦略
読み順序推定システムは、BBox座標情報を基に文書の自然な読み順序を推定します。各ページ内でy座標（上から下）を主軸、x座標（左から右）を副軸としてソートを行います。

#### 2.2.2 読み順序推定の詳細
- **座標ベースソート**: y座標を主軸、x座標を副軸とした並び替え
- **行検出**: 近接するy座標を同一行として扱う
- **カラム対応**: 複数カラムレイアウトの検出と処理

### 2.3 BBoxベース差分検出器 (BBoxBasedDiffDetector)

#### 2.3.1 アルゴリズム設計
差分検出器は、2つの文書のbbox_text_dataを比較し、追加・削除・修正を検出します。検出はページごとに実行され、位置情報と内容の両方を考慮します。

### 2.4 出力生成システム (OutputGenerator)

#### 2.4.1 ハイライト生成戦略
出力生成システムは、検出された差分と読み順序を元に、視覚的なハイライトを生成します。

**ハイライト対象**:
1. **読み順序**: 番号付き青色ハイライト
2. **差分箇所**: 色分けハイライト
   - 追加: 緑色
   - 削除: 赤色
   - 修正: 黄色

**出力形式**:
すべてのファイル形式（PDF、Word、PowerPoint）で元ファイルにハイライトを追加した形で出力されます。

## 3. データモデル設計

### 3.1 文書関連モデル

#### BBoxTextData
単語単位のテキストとその位置情報を格納するデータ構造です。bbox配列は[x, y, width, height]の形式で座標を保持し、pageフィールドでページ番号を管理します。

#### DiffResult
差分検出結果を表現するモデルで、変更タイプ（追加・削除・修正）、元のBBox情報、変更後のBBox情報、ページ番号、信頼度を含みます。

### 3.2 文書タイプ別BBox抽出実装

#### 3.2.1 PDF処理 (PyMuPDFService)
PyMuPDFライブラリを使用して、PDFから直接BBox情報を抽出します。各単語の座標情報を高精度で取得できます。

#### 3.2.2 Word処理 (DocxService)
Wordファイルは直接BBox情報を提供しないため、以下のアプローチを採用します：

1. **PDF変換方式（推奨）**: LibreOfficeまたはSpire.Docを使用してPDFに変換し、既存のPDF処理ロジックを再利用
2. **フォールバック方式**: 変換が失敗した場合、簡易的な座標推定でテキストのみを抽出

#### 3.2.3 PowerPoint処理 (PptxService)
python-pptxライブラリを使用して、スライド内のシェイプから位置情報を直接取得します。EMU（English Metric Units）をポイントに変換し、テキストフレーム内の単語単位で位置を推定します。

### 3.3 PDF変換サービス

#### LibreOfficePDFConverter
LibreOfficeのヘッドレスモードを使用して、Office文書をPDFに変換します。オープンソースで無料ですが、追加のインストールが必要です。

#### SpirePDFConverter
商用ライブラリSpire.DocとSpire.Presentationを使用した変換サービスです。高品質な変換が可能ですが、ライセンス費用が発生します。

### 3.4 Azure Document Intelligence統合

Azure Document Intelligenceは、スキャンされたPDFやOCRが必要な文書の処理に使用されます。PDFの場合は直接レイアウト解析が可能で、Word/PowerPointファイルは先にPDFに変換してから処理します。

## 4. API設計

### 4.1 RESTful API

#### メイン差分検出API
`POST /api/v1/document/compare`
- 2つの文書ファイルを受け取り、差分検出を実行
- ハイライト付きファイルのダウンロードURLを返却

#### ダウンロードAPI
`GET /api/v1/download/{file_id}`
- 生成されたハイライト付きファイルをダウンロード

#### プレビューAPI
`POST /api/v1/document/preview`
- ハイライトのプレビュー表示

### 4.2 WebSocket (リアルタイム進捗)
`/ws/comparison/{comparison_id}`
- 大規模ファイルの処理進捗をリアルタイムで通知

## 5. 性能最適化戦略

### 5.1 メモリ管理
MemoryOptimizedProcessorクラスは、メモリ使用量を監視し、閾値（デフォルト1024MB）を超えた場合にガベージコレクションをトリガーします。大規模文書はページ単位で分割処理されます。

### 5.2 並列処理最適化
ParallelProcessingOrchestratorは、ThreadPoolExecutorを使用してページ単位の並列解析を実現します。デフォルトでは4ワーカーで並列処理を行います。

## 6. エラーハンドリング設計

### 6.1 階層的エラー処理
エラーは以下の階層で管理されます：
- DocumentComparisonError: 基底例外クラス
- DocumentFormatError: 無効な文書形式
- BBoxExtractionError: BBox抽出失敗
- MemoryLimitError: メモリ上限超過

### 6.2 障害復旧戦略
- **フォールバック**: ファイルタイプ別の代替処理
- **グレースフルデグラデーション**: 部分的機能での継続動作
- **エラー通知**: 管理者へのエラー通知

## 7. セキュリティ考慮事項

### 7.1 データ保護
- **一時ファイル**: 処理後の即座削除
- **メモリクリア**: 機密情報のメモリ上削除
- **暗号化**: 保存時・転送時の暗号化

### 7.2 API制限
- **レート制限**: ユーザー・IP別のリクエスト制限
- **ファイルサイズ制限**: 100MB上限の厳格な実施
- **認証**: JWT トークンベース認証

## 8. 監視・ログ設計

### 8.1 メトリクス収集
PerformanceMonitorクラスは、以下のメトリクスを収集します：
- ファイルタイプ別の処理時間
- ファイルサイズと検出された差分数
- メモリ使用量とページ処理数

### 8.2 構造化ログ
すべてのログは構造化形式で出力され、comparison_id、ファイルサイズ、ユーザーIDなどのコンテキスト情報を含みます。

## 9. 品質保証戦略

### 9.1 テスト設計
- **単体テスト**: 各コンポーネントの独立テスト
- **統合テスト**: エンドツーエンドの差分検出テスト
- **性能テスト**: 負荷・メモリ使用量テスト
- **精度テスト**: 既知データセットでの検出率評価

### 9.2 人力評価プロセス
- **評価対象**: ハイライト付き出力ファイル
- **評価項目**:
  - 読み順序の正確性
  - 差分検出の正確性
  - 誤検出・見逃しの確認
- **評価シート**: 結果記録用テンプレート提供

この技術設計は、bbox_text_dataを中心としたPDF・Word・PowerPoint文書の差分検出システムの実現を目指しています。出力はハイライト付きファイルとし、人力での評価を前提としています。
