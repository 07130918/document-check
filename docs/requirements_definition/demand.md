# PDF差分検出システム 要求定義書

## 本ドキュメントの目的
本ドキュメントは、要望定義書で整理したお客様の要望を達成するために必要な機能要件・非機能要件等を定義し、システム開発の詳細な要求事項を共有するための資料です。

## 1. 機能要件

### 1.1 基本機能要件

#### 1.1.1 ファイルアップロード機能
- 2つのPDFファイルをアップロードできること
- アップロード可能なファイルサイズの上限を設定できること
- PDFファイル以外のアップロードを制限すること

#### 1.1.2 差分検出機能
- 2つのPDFファイル間の差分を自動で検出できること

#### 1.1.3 差分表示機能
- 検出した差分箇所にハイライト表示を行うこと
- 差分箇所に注釈を付与できること

#### 1.1.4 ファイルダウンロード機能
- 差分が注釈として追加されたPDFファイルをダウンロードできること
- ダウンロードファイル名は元のファイル名に基づいて生成すること

### 1.2 ユーザー管理機能

#### 1.2.1 ユーザー認証機能
- ユーザーID・パスワードによる認証を行うこと
- ログイン状態を一定時間保持すること
- 不正アクセスを防止するためのアカウントロック機能を有すること

#### 1.2.2 ユーザー管理機能
- ユーザーの登録・変更・削除ができること
- パスワードリセット機能を有すること

## 2. 非機能要件

### 2.1 性能要件

#### 2.1.1 システムパフォーマンス要件
- 処理時間: ファイルサイズに関わらず5分以内で処理完了すること
- 同時アクセス数: 最大3ユーザーの同時アクセスに対応すること

#### 2.1.2 差分検出性能要件
- **検出精度**
  - 検出率: 99~100%（見逃しゼロ）
  - 許容誤検出率: 10%以下
  - 注: 見逃しは絶対に許容できないため、多少の誤検出は許容する
- **検出対象**
  - テキストの差分を単語単位で検出（数字、記号、スペース含む）
  - フォントサイズ、色、スタイル等の書式変更は検出対象外
- **処理能力**
  - 最大処理ページ数: 60ページ
  - 最大ファイルサイズ: 20MB

### 2.2 セキュリティ要件
- 通信の暗号化: HTTPSによる通信の暗号化を行うこと
- アップロードファイルの取り扱い: 処理完了後は即座に削除すること
- アクセス制御: 認証されたユーザーのみがシステムを利用できること

### 2.3 保守性要件
- **📌 現在問い合わせ中**: ログ管理要件（保存期間、出力項目等）
- エラー発生時の通知機能を有すること

### 2.4 移植性要件
- **📌 現在問い合わせ中**: 対応ブラウザ要件

### 2.5 その他の非機能要件
- **📌 現在問い合わせ中**: バックアップ・リカバリ要件
- アクセシビリティ: 特別な要件なし

## 3. システム構成要件

### 3.1 システムアーキテクチャ
- Webアプリケーションとして構築すること
- クラウド環境（AWS、Azure等）上で動作すること
- スケーラビリティを考慮した設計とすること

### 3.2 クライアント要件
- 対応デバイス: パソコン（デスクトップ、ノートPC）
- 画面解像度: 1280×720以上を推奨
- **📌 現在問い合わせ中**: 対応ブラウザの詳細

### 3.3 ネットワーク要件
- インターネット経由でアクセス可能であること
- ファイアウォール等の制限がある場合は別途協議

## 4. 運用要件

### 4.1 運用時間
- 24時間365日利用可能であること（計画停止を除く）

### 4.2 監視要件
- **📌 現在問い合わせ中**: システム監視の詳細要件

### 4.3 サポート体制
- ヘルプデスク機能: 不要
- 運用マニュアルを提供すること

## 5. 制約事項
- 初期開発費用: お見積もり中
- 開発期間: 2025年8月末までに本番稼働

## 6. 前提条件
- インターネット接続環境があること
- 利用者はPDFファイルの基本的な操作ができること

## 7. 用語定義
| 用語 | 定義 |
|------|------|
| 差分 | 2つのPDFファイル間で異なる箇所 |
| ハイライト | 差分箇所を視覚的に強調する表示方法 |
| 注釈 | PDFファイルに付与するコメントやマーク |
